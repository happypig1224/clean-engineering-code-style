# 消除代码、注释与测试“AI味”工业级规范 (clean-engineering-code-style v2.0)

在 AI 辅助编程时代，大语言模型生成的代码往往呈现出**“局部语法完全合法，全局架构过度膨胀；行行挂满注释，句句全是废话；单测全绿，线上全崩；语言特性滥用，深水区陷阱重重”**的典型机器味综合征。

本规范专用于**彻底根除 AI 生成代码与注释中的机械坏味道，使交付的代码达到互联网大厂 P7+ 架构师 / 高级工程师的工业级水准**。

---

## 一、 核心工程哲学：信噪比法则 (Signal-to-Noise Ratio)

1. **代码是写给人维护的，顺便让机器运行**：自解释的代码结构远胜于千行废话注释。
2. **拒绝学术玩具型与对话助手型代码**：严禁在生产级代码中遗留任何 AI 的聊天腔调、无意义中间层和教学式注释。
3. **注释的核心是解释 Why，而不是 How**：代码本身告诉读者系统在**怎么做**，注释必须告诉读者系统**为什么这么做**以及**有什么潜在风险**。
4. **单测是防线，不是指标装饰品**：单测必须具备真实的“故障捕获能力”，绝不写为跑通覆盖率而自嗨的假测试。

## 二、 维度一：代码注释去“AI味”实战规范

### 1. 彻底消灭“废话文学”（Tautological Comments）
AI 最臭名昭著的特征是把代码翻译成白话并贴在上方。**任何读者扫一眼代码就能直接看懂的行内注释，一律严禁出现。**

* ❌ **典型 AI 废话注释示范**：
  ```java
  // 检查用户列表是否为空
  if (userList == null || userList.isEmpty()) {
      // 如果为空，返回空列表
      return Collections.emptyList();
  }
  // 遍历用户列表
  for (User user : userList) {
      // 将用户的年龄加 1
      user.setAge(user.getAge() + 1);
  }
  ```
* ✅ **工业级规范示范**：
  ```java
  // 优质代码自解释，此处完全无需注释
  if (userList == null || userList.isEmpty()) {
      return Collections.emptyList();
  }
  for (User user : userList) {
      user.incrementAge();
  }
  ```

---

### 2. 强制编写“意图型（Why）与约束型（Constraints）”注释
注释必须提供**代码本身无法表达的增量信息**：业务背景、魔数来源、时序依赖、并发锁约定、底层硬件或跨系统陷阱。

* ❌ **AI 机械复述示范**：
  ```typescript
  // 将重试次数设置为 3
  const MAX_RETRY_COUNT = 3;
  // 休眠 200 毫秒
  await sleep(200);
  ```
* ✅ **工业级意图与背景示范**：
  ```typescript
  // 下游统一网关在抖动时平均自愈时间为 180ms，重试 3 次可覆盖 99.2% 的瞬时网络颠簸，且避免超出整体网关超时硬限制 (1000ms)
  const MAX_RETRY_COUNT = 3;
  const RETRY_BACKOFF_MS = 200;
  ```

---

### 3. 严禁任何“AI 元标签与对话腔调”
代码文件中绝不可出现任何对话助手的残留印记：
- 严禁：`// Generated by AI Assistant` 或 `// According to your requirements...`
- 严禁：教学式步进注释 `// Step 1: Initialize variables`、`// Step 2: Query database`、`// Step 3: Return result`
- 严禁：客套与多余说明 `// Note: You can customize this function later if needed`

---

### 4. 拒绝“机械 Javadoc / Docstring 泛滥轰炸”（Docstring Bloat）
AI 喜欢给每个显然的 DTO、Getter/Setter、工具函数生成 10 行模板化文档，严重稀释代码视觉信噪比。
- **规范**：内部私有方法、简单 POJO 属性、含义不言自明的辅助函数，**严禁添加空洞的 `@param` / `@return` 模板**。
- **保留边界**：仅在**公共 SDK、对外暴露的 RPC/REST 接口、核心算法以及具有非直观副作用（如触发异步事件、修改全局上下文）的方法**上，编写严谨契约文档。

```java
/**
 * 扣减账户可用余额并记录冻结流水
 *
 * @param accountId 目标账户 ID，调用方须保证账户处于 ACTIVE 状态
 * @param amount    扣减金额（单位：分），必须为正整数
 * @throws InsufficientBalanceException 账户可用余额不足时抛出
 * @throws AccountFrozenException       账户已被风险控制系统冻结时抛出
 * @note 内部采用数据库行级排他锁 (SELECT ... FOR UPDATE)，禁止在外部事务中长时间持有，防止连接池耗尽
 */
public void debitAccount(Long accountId, Long amount) { ... }
```

## 三、 维度二：代码实现与架构去“AI味”实战规范

| AI 味代码坏味道 (Smell) | 机器化成因分析 | 大厂工业级重构标准 (Standard) |
| :--- | :--- | :--- |
| **过度设计与空心抽象** | AI 喜欢为一个 20 行逻辑套用 3 个接口、4 个工厂和 2 个策略类，结构看似复杂优雅，实则无法维护。 | **坚守 KISS 与 YAGNI**。在未出现 3 处以上真实异构实现前，不预设复杂抽象；禁止为只有单一实现类的服务强行创建虚假抽象。 |
| **反 DRY 样板代码复制** | AI 处理多处类似逻辑时，喜欢在各个分支复制代码块（如重复编写 JSON 反序列化与校验逻辑）。 | 提取高阶纯函数、通用工具类或声明式注解（如 Spring AOP / TS Decorator），消除硬编码拷贝。 |
| **幽灵 API 与幻觉依赖** | AI 凭模式推演捏造不存在的 SDK 方法，或混淆库的大版本 API（如在 v3 引用已废弃的 v1 方法）；甚至引入未在依赖清单中注册的第三方包（Slopsquatting 供应链隐患）。 | **严格遵循当前工程构建清单**（`pom.xml`, `package.json`, `go.mod`）。调用的每个 API 必须真实存在于当前依赖库中，严禁凭空臆造。 |
| **扁平化异常吞咽** | AI 极爱写 `catch (Exception e) { log.error("error", e); return null; }`，直接吃掉堆栈并返回 null，引发下游 NPE 灾难。 | **严格区分受检异常与运行时异常**。严禁捕获顶层 `Throwable/Exception` 后静默返回 null；必须分类捕获，透传业务错误码，完整保留 Root Cause 堆栈，确保分布式事务正常回滚。 |
| **魔数散落与硬编码** | AI 经常把状态码 `1`、超时时间 `5000`、缓存 key 前缀直接散落写死在代码分支深处。 | 统一提取为强类型枚举（Enum）或顶层不可变常量配置（`static final` / `readonly`），并注释其物理来源。 |

## 四、 维度三：主流语言生态特异性“AI 坏味道”专治

不同编程语言在大模型生成时有其特有的“语法糖滥用”或“模式幻觉”，必须针对性治理：

### 1. Java 生态专项治理
- **禁止滥用 `Stream` 炫技**：简单的集合查找、单层映射切勿无脑套用 5 层 `stream().filter().map().collect()`。尤其在超高频业务链路（QPS > 5000）中，简单的 `for-i` 或 `enhanced-for` 在可读性、调试断点与减少对象内存分配开销上远胜复杂 Stream。
- **禁止 `Optional` 泛滥**：`Optional` 仅用于方法返回值表示“可能缺失”。严禁将 `Optional` 用作方法入参、类成员属性或包装集合类型（`Optional<List<T>>` 是反模式，集合无数据应直接返回空集合 `Collections.emptyList()`）。
- **`BigDecimal` 精度陷阱**：严禁使用 `new BigDecimal(0.1)`（会产生 `0.1000000000000000055...` 的精度失真）。必须使用 `BigDecimal.valueOf(0.1)` 或 `new BigDecimal("0.1")`。
- **Lombok `@Data` 滥用警惕**：在 JPA/Hibernate 实体或深层嵌套 DTO 中，禁止无脑使用 `@Data`，避免其自动生成的 `equals()` 和 `hashCode()` 触发循环引用或递归懒加载引发 OOM。

### 2. Python 生态专项治理
- **可变默认参数陷阱**：严禁 `def append_item(item, target_list=[])`，默认参数在函数定义时创建，多次调用会共享同一个列表对象。必须使用 `target_list=None`，在函数内 `if target_list is None: target_list = []`。
- **上下文管理器缺失**：涉及文件 IO、Socket、DB 游标或锁操作，必须使用 `with` 语句包裹，杜绝手动 `close()` 在异常抛出时的资源泄漏。
- **字符串拼接反模式**：禁止在长循环中对字符串使用 `+=` 进行累加（每次都会申请全新内存块复制），必须将片段装入列表后使用 `"".join(chunks)` 批量组装。
- **滥用 `Any`**：严禁在类型注解（Type Hints）中通篇标注 `Any`，失去静态检查意义。

### 3. TypeScript / 前端生态专项治理
- **`any` 污染治理**：严禁为了让编译器闭嘴而通篇写 `: any`。优先使用精准的 Interface/Type，未知数据使用 `unknown` 并配合自定义类型守卫（Type Guards）。
- **`useEffect` 依赖项幻觉**：AI 极爱遗漏依赖项数组（导致闭包陈旧值引发幽灵 Bug），或在依赖项中放入未经 `useMemo` 的复杂对象引发无限重复渲染死循环。
- **内联回调重新分配**：避免在高频渲染列表的 JSX 内部直接声明大段匿名箭头函数，应提取为组件级函数或使用 `useCallback` 稳定引用。
- **异步四态完整性**：前端调用接口必须严密处理四种状态：`Idle`（初始）、`Loading`（加载中）、`Error`（失败重试）、`Success`（成功展示/空态 Empty）。

### 4. Go 生态专项治理
- **严禁静默丢弃 `err`**：禁止使用 `_ = doSomething()` 故意忽略错误，禁止在生产业务代码中无故调用 `panic()` 导致整个进程崩溃退出。
- **Goroutine 泄漏防范**：启动后台 Goroutine 必须传入 `context.Context` 并在外层可控取消；通道（channel）必须有明确的生产者关闭约定，防止接收方永久挂起。
- **并发 Map 读写安全**：Go 内置 `map` 不具备并发安全。并发读写必须使用 `sync.RWMutex` 加锁或使用 `sync.Map`，防止触发致命的 `fatal error: concurrent map writes`。

## 五、 维度四：架构、持久层与 SQL 实战避坑

AI 在生成数据库与分布式逻辑时，经常停留在教科书阶段，必须遵循大厂生产规约：

### 1. SQL 与持久层避坑
- **严禁 `SELECT *`**：即使是简单查询，也必须明确列出所需字段，防止索引覆盖（Covering Index）失效及表结构变更引发的网络带宽浪费。
- **深分页延迟关联**：禁止在百万级大表上直接写 `LIMIT 100000, 20`，必须改用**子查询延迟关联**或**基于游标（自增 ID）滚动查询**：
  ```sql
  -- ❌ AI 常见低效深分页
  SELECT * FROM orders ORDER BY id DESC LIMIT 1000000, 20;

  -- ✅ 延迟关联优化：先通过覆盖索引拿到 ID，再回表
  SELECT o.* FROM orders o 
  JOIN (SELECT id FROM orders ORDER BY id DESC LIMIT 1000000, 20) t ON o.id = t.id;
  ```
- **DDL 脚本幂等性**：AI 生成的迁移脚本经常漏掉条件判断，所有上线 SQL 必须具备幂等重入能力：`CREATE TABLE IF NOT EXISTS`、`ADD COLUMN IF NOT EXISTS`。

### 2. 高并发与分布式锁生产避坑
AI 最爱给出一个极其脆弱的 Redis 分布式锁实现。大厂标准锁必须具备三大要素：
1. **获取锁与超时时间原子化**：`SET key requestId NX PX 30000`；
2. **看门狗自动续期（Watchdog）**：防止业务耗时偶发超出超时时间，导致锁被自动释放引发并发安全事故；
3. **释放锁的原子校验**：必须通过 **Lua 脚本**比对 `requestId` 确认是自己持有的锁后再删除，严禁直接 `del(key)` 误删其他线程的锁。

## 六、 维度五：单元测试去“AI味”实战规范

AI 生成的测试用例往往具备高度欺骗性：代码看起来很长，CI 全绿，但根本防不住任何线上 Bug。必须推行三项去 AI 味治理：

### 1. 拒绝“全员 Happy-Path”假单测，强制覆盖边界矩阵
AI 默认只测试输入完全正确、各服务畅通无阻的“阳光大道”（Happy-Path）。
* **工业级规范**：强制编写**边界矩阵（Boundary Matrix）**测试用例：
  - **数值极端**：`0`、负数、最大值溢出（`Integer.MAX_VALUE + 1`）；
  - **集合与字符**：`null`、空列表、超长文本、SQL注入特殊字符、emoji；
  - **环境颠簸**：RPC 调用超时、DB 唯一索引冲突、分布式锁加锁失败、降级分支。

---

### 2. 拒绝“重言式测试”（Tautological Tests / Mock 自嗨）
AI 生成单测最经典的欺骗手段：给 Mock 对象打桩，然后断言 Mock 对象的返回值，完全没有验证被测类的实际处理逻辑。

* ❌ **AI 重言式假单测**：
  ```java
  // 伪测试：给 mockRepo 打桩，然后断言 mockRepo 返回的数据，被测服务核心计算逻辑完全没覆盖
  when(mockRepo.getUser(1L)).thenReturn(mockUser);
  User result = mockRepo.getUser(1L);
  assertEquals("Alice", result.getName());
  ```
* ✅ **工业级行为验证单测**：
  ```java
  // 真实测试：验证被测 service 在获取到底层数据后，业务计算、状态流转与外部副作用
  when(mockRepo.getUser(1L)).thenReturn(new User(1L, "Alice", UserGrade.VIP));
  
  OrderDiscount discount = orderService.calculateDiscount(1L, new BigDecimal("100.00"));
  
  assertEquals(new BigDecimal("20.00"), discount.getDiscountAmount());
  // 校验关键副作用：是否正确触发了审计日志记录
  verify(mockAuditLogger, times(1)).logDiscountApplied(eq(1L), any());
  ```

---

### 3. 拒绝“幽灵断言”（Ghost Assertions）
- ❌ 仅执行被测方法 `service.processOrder(order)`，最后只写一个 `assertNotNull(result)` 甚至没有任何 `assert`。
- ✅ **深度断言规范**：
  - 核心业务字段逐项断言（订单状态是否由 `INIT` 变为 `PAID`）；
  - 异常断言必须精准到**异常类型与具体错误码**：
    ```java
    BizException ex = assertThrows(BizException.class, () -> orderService.pay(orderId));
    assertEquals(ErrorCode.BALANCE_INSUFFICIENT, ex.getErrorCode());
    ```

---

### 4. 统一 AAA 结构与语义化命名范式
测试方法命名必须遵循 Given-When-Should 或 Should-When 行为命名法，严禁出现 `test1()`, `testUser()`, `testMethod()` 这种 AI 随意命名的代码。
- **命名范式**：`should_throw_exception_when_balance_insufficient`
- **代码结构**：必须清晰划分 **Arrange（准备上下文）**、**Act（执行目标操作）**、**Assert（断言验证结果）**。

## 七、 维度六：研发元协作（Git Commit & API 契约文档）

### 1. Git Commit 提交信息去 AI 味
- ❌ **AI 提交恶习**：
  - 泛泛而谈：“Update code according to instructions”、“Fix bugs and optimize functions”；
  - 冗长罗嗦：生成一整篇包含思考过程的长篇大论。
- ✅ **大厂 Angular 语义化提交标准 (Conventional Commits)**：
  - 格式：`<type>(<scope>): <subject>`
  - 示范：`feat(trade): implement distributed lock for inventory deduction`
  - 示范：`fix(auth): resolve token refresh race condition on token expiration`

### 2. Swagger / OpenAPI 接口文档去 AI 味
- ❌ **AI 复述式文档**：
  - `@ApiModelProperty("用户ID") private Long userId;`
  - `@ApiModelProperty("状态") private Integer status;`
- ✅ **大厂严谨契约文档**：
  - 必须写清**业务来源、合法枚举取值范围与边界约束**：
  ```java
  @Schema(description = "统一交易订单号，全局雪花算法生成，长度固定19位", example = "1758291048291048291", requiredMode = RequiredMode.REQUIRED)
  private Long orderId;

  @Schema(description = "订单支付状态：1-待支付，2-支付中，3-支付成功，4-超时关闭", allowableValues = {"1", "2", "3", "4"}, example = "1")
  private Integer payStatus;
  ```

## 八、 工业级 Code Review 12 项门禁检查单 (CR Gate Checklist)

在提交 PR 或自检 AI 编写的代码时，必须逐条对照通过：

- [ ] **1. 无复述废话**：没有一行注释是在把下一行代码重新用自然语言翻译一遍。
- [ ] **2. 无 AI 元印记**：代码中不存在 `Generated by AI`、`Step 1/2/3` 或助手对话式客套。
- [ ] **3. Why 与约束就位**：核心业务算法、魔数、并发加锁、重试延迟处均有清晰的意图与边界说明。
- [ ] **4. 严禁 Docstring 泛滥**：无脑 getter/setter 与内部简单辅助方法无冗余 Javadoc 模板。
- [ ] **5. 无虚假抽象**：没有为了一个单例实现引入 4 个抽象层，严格遵守 KISS 原则。
